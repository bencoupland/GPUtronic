# Two SMs stay free

The light desktop held 60 fps with 0, 1, 2, and 4 SMs left empty. The compiled reserve stays 2. Spare 2 had the tightest compositor clock. Spare 0 also held this 12-second sample, with a wider tail, because the driver time-sliced SMs that already had a resident block. Spare 4 had one doubled interval. One short sample of a moving rectangle and one ordinary browser window is enough to keep 2, and too thin a sample to drop the reserve to 0 or raise it to 4.

All of the numbers below were measured on this RTX 5080 on 12 October 2026, from 17:02 to 17:04 local time. Driver 595.99.02. The binary was built with CUDA 12.8 for `sm_120`. `nvidia-smi` prints CUDA 13.2. Nothing here is modelled. Kp stayed 0.55, Ki stayed 0.08, and the deadband stayed 0.08. The clamp formula was not edited. `GPUTRONIC_PULSE_LOCAL` and `GPUTRONIC_CTRL_CACHE` were unset. The question was present timing. The pulse-rate lines in the gold logs are the stock self-test during the hold. They are not a comparison of 84, 83, 82, and 80.

Logs: `logs/2026-10-13_spare-sm/`.

## What was timed

The spare is SMs with no test block. A launched block keeps its SM while it works and while it waits, so commanding a lower `active_sms` does not free one. `GPUTRONIC_OS_RESERVE` set the launch count for one run. The compiled default stayed 2.

Each hold was `gputronic_gold noise <launch> 50`. That is open loop at the launch count, so every launched block was in the work loop. The present probe started after `[LOAD] calibrated`. `GPUTRONIC_NO_CSV=1` skipped the 10 µs control file and the binned trace, so those host writes were not in the frame timing. The fast files were deleted at the end of each hold.

The display was DP-0, primary, 3840×2160, 621×341 mm. The compositor refresh interval on every kept frame was 16668 µs, which is 60 Hz. The window under test was a GTK 3 frame-clock window, 960×540, titled "GPUtronic present probe", drawing a moving rectangle for 12 seconds. GTK's frame clock is the clock Cinnamon drives for a normal window. A redirected GL swap can return without waiting for the display, and the GLX headers are not installed on this machine, so the probe used the frame clock.

The browser was one new Firefox window on `http://127.0.0.1:8877/`, raised to 140,700 and requested at 1100×720. Firefox reported an inner size of 917×527, CSS screen 3200×1800, device pixel ratio 1.2, and `hidden=False`. 3840/1.2 is 3200, so the page was on the 4K output. The page recorded `requestAnimationFrame` intervals for 12 seconds. The titled window was closed with `wmctrl`. Firefox itself was not killed.

The decision metric drops the first 500 ms, then counts intervals over 20 ms and intervals over 33.4 ms. A 60 Hz vblank is 16.7 ms. An interval over 33.4 ms has missed one.

An idle window, 4 seconds and no Gold grid, kept 211 frames: median 16.65 ms, p99 18.23 ms, max 18.61 ms, none over 20 ms. An idle browser, 6 seconds and no Gold grid, kept 331 frames: median 17.06 ms, p99 17.12 ms, max 17.12 ms, none over 20 ms. That browser window was 1600×999. The loaded browser clock matches it, so the steady 17.06 ms spacing is Firefox's callback timestamp. 691 kept frames in about 11.5 seconds is one callback per vblank.

## What changed in the source

`gputronic_create` still subtracts the spare when the caller asked for the whole device. `GPUTRONIC_OS_RESERVE`, when set, replaces the 2 for that process. A negative value becomes 0. The spare cannot eat into the command floor of 2. Unset keeps 2, and the process prints the override only when the variable is set. The lines are 1150–1162 of `src/gputronic_gold.cu`.

`GPUTRONIC_NO_CSV=1` skips the 10 µs file in `gputronic_start` (lines 1304–1309) and the binned trace in `gold_load_run` (lines 1928–1929). Unset keeps both files. The function frame has a row for each switch. `GPUTRONIC_RESERVE_SMS` is a different field, the extra SMs kept on above the calibrated starting count, and it stayed 0.

Gains, the deadband, and the clamp formula were not edited. The three checks were not re-run. With both variables unset, the launch count and the CSV path are the same as on `863898a`.
