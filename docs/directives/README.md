then, only if exit stayed in band, the 1.2 load-step run that drives Z outside the 0.08 band so the PI corrections can be measured), with a continuation of the tenth pass (merge the ninth-pass results to main if not done; find out why the guest kernel did no work beside Gold under idle-exit and fix its scheduling so freed SMs reach a second kernel at any load; then widen the integral clamp as a test setting on the full-pipe 1.2 load step, which sat on the clamp in every loaded hold; no custom drivers or per-SM sleep), and eleventh (Z = 1 as the home state with commanded Z as the opt-in deterministic mode; the integral clamp measured as a guardrail by trip rate, with the 15-SM run to finish the sweep and an upstream look at the down-step regression; repeat the heavy real-work load at 15 SMs at Z = 1.5 and Z = 1.0 to tell whether the twelfth pass's return miss is variance, a regression, or real; and sweep the heavy step size at the compiled 3.28 SM clamp (1.2, 1.1, 1.05, with repeats) for a trip-rate curve; shorter windows, 30 s floor for clamp tests), and fourteenth (three probes on a hunting run at clamp 15, Z = 1.5: log SM count and Z every control cycle by keeping the per-tick file; raise the control rate on a low-`rate_ref` run, through the control-word cache and a test-only rate-window switch, to see whether the hunting stops; and tell whether the 47 against 49 million `rate_ref` split comes from loop latency or the workload, with repeated open-loop `fullwidth` calibrations, the work and per-SM counters, and display state logged; a slow 0.8 to 1.2 to 0.8 ramp and 0.025 stairs; closed-loop confirmations only at high-group points, against a same-session low-group baseline; 30 s windows, 10–15 s sweep points, SM count and Z logged every control cycle).

They are records of what was asked at the time. The branch names and commit hashes in them (`test-results/...`, `controller-fixes`) are where the code lived when each pass ran. All of those results branches, through `test-results/2026-10-13_full-pipe`, are now part of `main`, so the code each directive points to is in `main`'s history.

Since `b8b66e7` the project is spelled GPUtronic, and the control structs are `GPUtronicControl`, `GPUtronicHandle` and `GPUtronicConfig` in `include/gputronic.h`. The directives use those names. The `GPUTRONIC_*` environment variables are unchanged.
