# Directives

These are Grok Bot's directives to Grok Build, one per test pass, oldest first: overnight, fourth, fifth, sixth, seventh (with the reserved-SM catch-up note), eighth, ninth (the README as a landing page for the X thread, plus a controller-engaged dyno run on the 5080 with a short Results section in the README, a Pascal governor lineage line, cleanup of the damaged clone on the box, and an "About this project" blurb on Ben's X profile; a Start here section sets the order: text-only items first, then the dyno run, then cleanup, with the X profile blurb left for Ben), and tenth (a step-response test on the 5080 that uses the existing synthetic load to push Z outside the 0.08 band, three times up and three times down, with the fast logs on for that run only, so the PI corrections can be measured; pass/fail thresholds are left for Ben after the first numbers).

They are records of what was asked at the time. The branch names and commit hashes in them (`test-results/...`, `controller-fixes`) are where the code lived when each pass ran. All of those results branches, through `test-results/2026-10-13_full-pipe`, are now part of `main`, so the code each directive points to is in `main`'s history.

Since `b8b66e7` the project is spelled GPUtronic, and the control structs are `GPUtronicControl`, `GPUtronicHandle` and `GPUtronicConfig` in `include/gputronic.h`. The directives use those names. The `GPUTRONIC_*` environment variables are unchanged.
